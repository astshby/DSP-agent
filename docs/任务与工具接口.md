# v1.0 任务与本地工具接口

网页手动输入、离线规则助手、Node 工具调用都使用 `src/dsp.js` 的 `DSP.runAnalysis(task)`。没有动态执行用户/模型代码，也没有把按钮坐标交给模型。规则助手在 `src/assistant.js` 中，支持有限自然句式和参数提取，未知或冲突内容要求补充。

## 任务格式

```json
{
  "schemaVersion": 1,
  "input": {
    "kind": "manual",
    "values": [1, 2, 1],
    "n0": -1,
    "sampleRateHz": 1000
  },
  "operations": [
    {"type": "convolve", "kernel": [0.5, 0.5], "n0": 0},
    {"type": "spectrum", "method": "fft", "window": "hann", "nfft": 4, "removeMean": false}
  ]
}
```

发生器输入见 `examples/08-filter.json`。导出时数字规范化，手动/CSV 样值写入 values；不保存机器绝对路径。最多 4096 个实样值、8 步操作；每步输出也受长度约束。

| type | 参数 | 说明 |
|---|---|---|
| transform | gain, shift, reverse | 先反折再移位，shift 是整数 |
| convolve | kernel, n0 | h 的样值与首项下标；完整线性卷积 |
| difference | b, a, xHistory, yHistory, tail | 按 z⁻¹ 升幂系数；历史最近项在前；tail 为非负整数 |
| dtft | 无 | 当前有限序列的 257 点 DTFT 显示采样 |
| response | b, a | 单位圆上 H 的代数求值，存在条件另行说明 |
| zplane | b, a | 各最多 3 项，低阶零极点与因果 ROC |
| inverse_z | pole, side | side 为 right/left；典型一阶逆变换 |
| zvalue | radius, angleDeg | 有限序列在给定复数 z 求值；radius>0 |
| spectrum | method, window, nfft, removeMean | method=dft/fft；window=rectangular/hann/hamming |
| filter（FIR） | family, response, cutoffHz, taps, window | family=fir；response=lowpass/highpass；奇数抽头 3—129 |
| filter（IIR） | family, response, cutoffHz | family=iir；固定二阶 Butterworth |

前端表单可接受数值字符串，由 DSP 层规范化。**模型工具契约只接受规范化数字和明确字段**，不会把字符串 `'100 Hz'` 当 number；未知工具、未知字段、缺失参数、越界数值均拒绝。工具的完整 JSON Schema 在 `server/contracts.cjs`，实际可读取 `GET /api/tools`。模型服务是否原样支持该 schema，需要相应适配器验证；不能据本地测试宣称两家 API 已兼容。

结果包含 `task`（规范化）、`original`、`signal`（最终输出）、`steps`（每步信号）、`analyses`（分析结果）、`metrics`、`warnings`。DTFT/频谱相位在幅度接近零时是 null，频响奇点为 null，不写 NaN/Infinity。

## HTTP 接口（当前已实现）

启动 `npm start` 后，网页和 API 同源。监听 127.0.0.1:8787，可通过 DSP_PORT 修改端口。请求体上限 1 MiB，仅接受 JSON。

| 方法 / 路径 | 输入 | 输出 |
|---|---|---|
| GET /api/health | — | 版本、local-agent 模式、cloudProvidersEnabled=true |
| GET /api/providers | — | OpenAI/DeepSeek 模型 ID、官方地址、configured；不返回密钥 |
| POST /api/providers | `{providerId, model, apiKey?}` 或 `{providerId, remove:true}` | 保存/删除后的脱敏配置；空 Key 保留原值 |
| POST /api/providers/test | `{providerId}` | 实际模型 + 空操作分析工具测试，带 trace/result |
| GET /api/tools | — | 两个工具的名称、说明与 schema |
| POST /api/signals | `{input}` | signalId、采样信息和统计量 |
| POST /api/tools/call | `{name, arguments}` | 工具结果摘要 |
| POST /api/agent/preview | `{text, task, settings?}` | 规则计划：ready 或 needs_input、changes 与参数来源，不替换网页结果 |
| POST /api/agent/runs | `{providerId, signalId, text, operations}`，或原 `{mode:"mock", signalId, operations}` | 解释 text、工具 trace、resultId、云模式下完整本地 result |
| GET /api/results/:id | — | 本地完整结果，供网页绘图 |

失败为非 2xx，JSON `{error:{code,message}}`。限制 HTTP Host/Origin 为本机同源，不启用跨域通配；静态文件只提供显式允许的页面文件，不暴露 .git、配置或任意磁盘路径。内存缓存每类最多 32 项，超限按最早入库淘汰，重启清空。

## 已实现的模型循环

`server/providers.cjs` 将两家官方 Chat Completions 请求/响应映射到 `next({messages,tools,signal})` 协议，返回工具调用或说明文字。适配器保存本次运行的 assistant/tool 成对消息，工具定义来自 `server/contracts.cjs`。密钥仅放在官方请求的 Authorization 头，不写入消息。

Runner 最多 6 轮、共 8 次工具调用、每轮最多 4 次、总计 90 秒；同时最多两个云端任务。工具参数错误作为工具结果返回模型，允许在额度内修正。未知工具、其他 signalId、无效参数均拒绝；最新分析失败则不保留上一次成功分析作为待应用结果。工具为同步且受样本/运算上限约束，并非通用代码沙箱。

浏览器先登记当前输入，然后发送用户文字和规范化的当前 operations。模型仅收到 signalId、采样元数据、统计、操作参数和摘要；输入样值不自动发往供应商。用户主动写入文字的内容和卷积核/差分系数属于请求内容。模型当前只能分析已登记信号，不能通过工具生成新信号或读文件。

云端返回时，浏览器用 DSP 复算并核对，显示待应用步骤；用户应用后才替换图表。输入变化使旧预览失效；请求期间改变实验会丢弃响应。取消 fetch 使 HTTP 连接关闭，后端传播 AbortSignal 取消供应商请求。已完成的远端 token 可能仍计费。本地 DSP 同步计算不支持逐指令中断。

首版为整次返回 JSON，不提供 SSE/逐字流式。没有持久聊天会话；下一次请求从当前任务重新建立上下文。无自动重试，避免意外重复计费。HTTP 401/403/404/429 等显示固定说明，不回显供应商错误正文。MockProvider 仍供不联网自检。

密钥默认存在用户目录 `.dsp-agent/providers.json`；可用 `DSP_CONFIG_DIR` 指向项目之外的专用目录。原子写入，Unix 文件权限 600。官方地址写死，不支持任意代理 URL。配置 API 不返回 Key，静态文件白名单不公开配置。真实供应商账号调用未在云环境执行，详见《模型使用与首版验收》。

## v0.9.2 的规则计划与页面上下文

`RuleAssistant.plan(text, task, settings)` 可接收当前页面的 `settings.filter` 与 `settings.spectrum`；字段名称与对应任务操作一致，去掉 type 即可。规则会从常用句式提取 Hz/kHz、FIR/IIR、低通/高通、抽头/阶数、窗函数、DFT/FFT 点数等。

新建操作的优先级：文字明确指定 → 页面设置 → 有说明的默认值。修改操作的优先级：文字明确指定 → 原操作 → 页面设置 → 默认值。裸数值不静默补成 Hz；不把“不要低通”误当低通执行。缺失必要信息、互相冲突的参数、未知剩余内容会返回 needs_input，且 task=null，不部分执行。

“改成/换成”等表达会定位当前任务中最近的对应滤波或频谱步骤。比如 `[filter, spectrum]` 接收“截止改成 150Hz”后只替换 filter，并用整个任务重算 spectrum；没有对应步骤时要求先新增。上下文来自当前可复现任务，没有隐蔽的聊天记忆。

成功结果附带 `changes:[{mode:"append"|"replace", index, operation, sources}]`，其中 index 从 0 开始，operation 已通过共享 DSP 校验；sources 标注“文字 / 页面设置 / 上次操作 / 默认值 / 按信号长度”。前端把它显示为中文计划，用户执行后同步参数面板。任何影响计划的页面输入变化都会使旧预览失效。

第 10、11 次已复用任务与 DSP 校验，增加独立的云端结果预览、官方协议适配和消息映射；模型不操作 DOM。


## 每周能力子集（v0.9.2）

共享解析器新增 `plan(text, task, settings, profile)` 的可选第四参数，默认第十三周全集。历史页面传入 `CourseCapabilities.forWeek(week)`，每个操作在构建/执行计划前必须通过该周清单；实际数值验证仍交给原周页面中的 DSP。完整计划通过才可执行，不出现半句成功后半句失败的部分执行。

计划支持 input（修改输入）、inspect（读取指标）及已存在的 DSP 操作。input/inspect 是界面计划类型，不写进 `task.operations`，因此第五周仍满足 operations=[] 的原 DSP 契约，也不改变模型 `run_analysis` 工具的操作 schema。差分、频响与 z 分析复用既有操作字段。预览响应的 changes.mode 增加 input/inspect，此时 index=null；append/replace 仍为操作数组下标。

第 5—12 周独立 HTML 的助手及能力定义由 `scripts/backfill-assistants.cjs` 内嵌，模型服务和文件保存功能不会随助手一起提前出现。支持范围与入口见 `每周离线助手.md`。
