# DSP Agent：离线实验台与第 5—15 周提交规划

本规划依据仓库中的课程任务书、参考案例，以及所提供的王世一《数字信号处理》扫描版目录制定。第 5—15 周共 11 次提交。“第 6 次提交”按第 10 周计算，并作为第二章结项节点。用户已学习到第二章末尾，前六次交付用于把已学知识做成可运行实验；这里安排的是项目开发节奏，不推定新的授课进度。

当前已提供第 1—11 次提交，最新为 v1.0.0 / 第 15 周。第 6 次完成第二章代表性实验；第 7、8 次完成频谱和滤波；第 9 次完成离线复现与本地工具接口；第 10、11 次实现 OpenAI、DeepSeek 官方 API 适配、配置与预览。工程与模拟协议验证已完成，真实 API 账号验收留在用户本机完成。入口见根目录 README 和 `docs/模型使用与首版验收.md`。下列初始规划中的扩展功能不代表全部实现，最终边界以首版验收说明为准。

模型顺序为 OpenAI API → DeepSeek API。运行形态、密钥存储、工具调用流程及源码参考见[模型接入工程方案](模型接入工程方案.md)。Agent 正式接入后移到第 10、11 次提交（第 14、15 周）；第 9 次准备本地后端及工具契约，凭据可用时进行最小真实调用验证。前六次聚焦第二章，不安排模型接入。

## 1. 最终效果与范围

目标是一个个人使用的网页信号分析实验台：生成或导入信号，设置分析操作，查看处理前后的波形、频谱和数值，保存实验配置与结果。

最终保留三个操作入口，随着课程逐步开放：

| 入口 | 用户如何操作 | 是否需要模型 |
| --- | --- | --- |
| 手动操作 | 选择信号、算法和参数，点击运行 | 不需要，完整支持离线 |
| 规则助手 | 输入有限的命令，例如“计算卷积”“分析频谱” | 不需要，仅识别已支持的表达 |
| 模型助手 | 用自然语言描述多步需求，由模型组织任务 | 使用所选模型；调用云端服务时需要联网 |

三个入口都生成相同的任务配置，经同一套校验后交给本地 DSP 程序执行。离线网页无需为了模型助手重做。模型服务不可用时，手动操作和规则助手仍可使用。

范围控制：先支持单通道、有限长度、实数序列；主线覆盖第 1—5 章，其中第二章用六次交付完成。第 6 章谱估计与第 7 章量化演示降为可选扩展，第 8 章参考软件实现思路。第二章的 z 变换用典型序列、低阶系统及性质实验覆盖；通用符号代数求解器、硬件采集、多通道、实时音频和高级参数谱估计不进入必做范围。

## 2. 推荐功能选项

这是最终功能清单；每周界面只开放已完成并验证的功能。

### 2.1 信号来源

| 选项 | 参数与行为 | 优先级 |
| --- | --- | --- |
| 预设实验 | 一键载入信号、参数与说明；例如“卷积”“双频滤波”“频谱泄漏” | 主线 |
| 信号发生器 | 正弦、余弦、单位脉冲、单位阶跃；逐步加入双频叠加和可重复噪声 | 主线 |
| 手动序列 | 输入数值和首项下标；卷积时再输入 h[n] | 主线 |
| CSV 导入 | 选择数值列；可选时间列；没有时间信息时补充采样率 | 主线 |
| 方波、三角波 | 用于观察谐波及采样影响 | 扩展 |

发生器常用参数：采样率 fs（Hz）、样本数 N、频率 f（Hz）、幅值 A、相位（度）、直流偏置。双频信号再显示第二组频率和幅值；噪声再显示强度与随机种子。

“预设实验”与“可调发生器”并存：前者方便每周演示和结果复现，后者方便探索参数。

CSV 第一版约定为 UTF-8、逗号分隔，允许表头，支持单列数值或时间/数值两列。预览前若干行，选择列和时间单位。非数值、空数据、不等间隔时间应给出具体提示，不能静默填零或假设等间隔；自动重采样以后再考虑。纯序列没有 fs 时仍可绘制下标图、做卷积和统计；输出 Hz 频率或按 Hz 设计滤波器前必须有有效 fs。

### 2.2 分析与处理

| 操作组 | 推荐选项 | 页面需要展示的参数 |
| --- | --- | --- |
| 时域查看 | 原始/处理后波形、叠加对比 | 下标或时间轴、显示区间 |
| 序列操作 | 缩放、移位、反转、去均值 | 倍数、移位量 |
| 卷积 | 线性卷积 | h[n] 数值、首项下标 |
| 频域分析 | 幅度谱、相位谱、主频估计 | DFT/FFT、窗函数、变换点数 |
| 数字滤波 | FIR 或 IIR；按已实现的响应类型选择 | 见下表 |
| 基础指标 | 均值、RMS、峰峰值、有限序列能量 | 通常不需要额外参数 |
| 基础谱估计 | 周期图功率谱密度 | 采样率、窗函数；与幅度谱区分单位 |

DFT 与 FFT 是同一变换的不同计算方法，放在频域分析的“计算方法”中。滤波器属于处理算法，在选择“滤波”后再展开其专用参数，避免把层级不同的选项混在一个下拉框里。

### 2.3 滤波器选项

| 层级 | 选项与实现顺序 |
| --- | --- |
| 是否处理 | 不滤波 / 应用滤波器 |
| 实现类别 | 移动平均（FIR 入门预设）→ 窗函数法 FIR → Butterworth IIR |
| 频率响应类型 | 先低通；再增加 FIR 高通；带通、带阻为扩展 |
| FIR 参数 | 系数个数（抽头数）、截止频率、设计窗；阶数 = 抽头数 − 1 |
| IIR 参数 | 先固定二阶 Butterworth 低通，只让用户调整截止频率；更高阶为扩展 |
| 结果 | 输出波形、处理前后频谱、滤波器幅频响应；说明瞬态和延迟 |

移动平均本身属于 FIR。信号频谱分析所用的窗与 FIR 系数设计所用的窗是两个独立参数，分别放在对应面板中。

默认校验包括：fs > 0；样本数有效；数值有限；0 < 截止频率 < fs/2；滤波器参数在已支持范围内。采样混叠实验可刻意生成超过奈奎斯特频率的信号，但要明确标为实验并解释折叠现象。

### 2.4 保存与复现

- 导出原始或处理后的 CSV。
- 保存实验配置 JSON：信号来源、采样信息、处理操作、参数和随机种子。
- 对导入文件，配置中保存数据标识和采样元数据；完整复现包需另带原始 CSV，不能承诺仅凭文件名恢复数据。
- 保存图像或页面报告，附本次实验的关键参数和结论。
- 提供恢复预设和清空处理；保留原始数据，便于前后对照。

## 3. 页面布局

沿用参考案例的桌面端三栏结构，但先把手动实验操作作为主入口。

| 区域 | 建议内容 |
| --- | --- |
| 顶部 | 项目名、当前版本、预设实验、导入/导出、已实现的操作模式 |
| 左栏，约 25% | 信号来源 → 信号参数 → 分析/处理选项 → 对应参数 → 运行/重置 |
| 中栏，约 50% | 上方时域波形；下方频域结果；原始与处理后数据可叠加；卷积实验展示 x、h、y |
| 右栏，约 25% | 数据摘要、关键指标、参数校验、操作记录；后续增加规则/模型助手标签页 |
| 底部可折叠区域 | 本次实验说明、相关公式和完整任务 JSON |

窄屏时依次排列输入、图形、结果。未到频谱阶段时，中栏只显示已经实现的时域内容；任务 JSON 默认折叠，在调试或课堂解释接口时展开。

典型流程：选择“双频滤波”预设 → 检查 fs 与两个频率 → 选择 FIR 低通 → 点击运行 → 对照时域、频谱和幅频响应 → 保存实验结果。

## 6. 规则助手与模型助手如何连接

参考案例当前只用关键词判断操作，数值和下标来自表单；它不会从任意自然语言中完整提取序列。

推荐逐步发展：

1. 第 5 周建立 `runAnalysis(task)` 的统一入口；手动表单负责组装 task。
2. 每周提供与当周能力对应的离线规则助手，前六次重点完成第二章实验。
3. 第 13 周统一离线规则、参数来源与配置复现，准备本地模型后端和最小工具验证；前面各周使用相同解析器的能力子集。
4. 第 14、15 周分别完成 OpenAI、DeepSeek 的正式集成，使用相同的校验器和 DSP 执行器。

模型需要知道的是操作名称、参数类型、单位、合法范围、当前信号 ID/采样率/样本数等摘要，以及结果/错误格式。它无需了解按钮坐标或整个网页 DOM。CSV 导入仍由用户选择文件，模型通过已载入的数据 ID 使用它。

示意任务如下，具体字段在实现时统一：

```json
{
  "schemaVersion": 1,
  "inputId": "signal_1",
  "operations": [
    {
      "type": "filter",
      "family": "fir",
      "response": "lowpass",
      "cutoffHz": 100,
      "taps": 51
    },
    {
      "type": "spectrum",
      "method": "fft",
      "window": "hann"
    }
  ]
}
```

这里的 fs 等元数据随 `signal_1` 存储；校验器核对这些信息后才能执行。操作按列表顺序执行，保存原始数据和各步结果以便比较。模型输出作为待校验的数据，不直接运行模型生成的代码。模型解释只引用已计算的结果。

## 7. 离线交付与数值检查约定

离线版使用本地 HTML、CSS、JavaScript 和随包提供的依赖；交付可双击打开的页面，不依赖 CDN。开发过程可以使用构建工具，最终包需要用文件方式实际检查。模型模式由启动脚本开启 Node.js 本机服务并打开其提供的网页；网页和 API 同源，凭据由后端保存在用户配置目录。DSP 算法和校验写成浏览器与 Node.js 共用的模块。

模块建议分成页面、信号数据、DSP 算法、任务校验、助手适配五部分，保持足够简单。先不选重型 Agent 框架。

数值验证应围绕可能出错的行为：

- 卷积：数值、长度和起始下标；单位脉冲、负下标与零序列。
- 频谱：DC、奈奎斯特点、单边幅度标定；相位在幅值接近零时不作可靠解释；窗口增益修正；DFT/FFT 对照。
- 滤波：与独立实现交叉核对；使用相同初始条件；标明瞬态，不能直接把不同延迟的输出逐点相减当作误差。
- 噪声与 PSD：固定种子，明确窗能量归一化、单边谱和单位；若做去均值，功率参考采用处理后的数据。
- 任务入口：手动、规则和模型提交相同任务时，DSP 结果一致；未实现操作和错误参数被拒绝。

参考来源：`课程项目-任务书与参考案例-学生发布包/任务书/index.html`、`参考案例/index.html`，以及本次提供的课本扫描 PDF。规划不替代教师后续发布的授课安排或验收要求。
